# AdminHub — швидкі шляхи в адмінки

Один додаток для всіх сайтів: менеджер обирає сайт → бачить зрозумілі розділи («Сторінка товару», «Головна», «SEO»…) → в один клік відкриває потрібне місце в адмінці. Працює на комп'ютері й телефоні, встановлюється на телефон як застосунок (PWA).

**Можливості**
- Пошук по всіх сайтах одразу (`/` або `Ctrl+K`), стрілки + Enter — відкрити.
- Фільтр усередині сайту, швидкі переходи між розділами.
- Обране ☆ та «Нещодавно відкривали».
- Режим «Редагувати»: додати сайт, розділ, посилання, змінити порядок, перенести посилання в інший розділ.
- Ролі: **Перегляд**, **Редактор**, **Адміністратор**.
- Експорт / імпорт JSON (бекап і масове заповнення).
- Світла й темна тема.

---

## 1. Спробувати без Firebase (демо)

Поки у `firebase-config.js` порожній `apiKey`, додаток працює в демо-режимі: вхід з будь-яким email, дані зберігаються лише в браузері.

```bash
cd adminhub
python -m http.server 8000
# відкрити http://localhost:8000
```
> Відкривати через `file://` не можна — потрібен локальний сервер.

---

## 2. Налаштування Firebase (≈10 хв)

1. **Створити проєкт** на <https://console.firebase.google.com> (Google Analytics не потрібен).
2. **Додати Web-застосунок**: Project settings → General → *Your apps* → `</>`. Скопіювати об'єкт `firebaseConfig` у файл **`firebase-config.js`**.
3. **Authentication** → Get started → Sign-in method → увімкнути **Email/Password**.
   - Authentication → **Settings → User actions** → зняти галочку **«Enable create (sign-up)»** (закриває самостійну реєстрацію).
   - Authentication → **Settings → Authorized domains** → додати `ВАШ-ЛОГІН.github.io`.
4. **Firestore Database** → Create database → режим **Production** → регіон `europe-west` (або найближчий).
5. Firestore → **Rules** → вставити вміст файлу **`firestore.rules`** → *Publish*.
6. **Створити першого адміністратора:**
   - Authentication → Users → **Add user** → ваш email + пароль.
   - Firestore → Data → *Start collection* `members` → **Document ID = ваш email маленькими літерами** → поле `role` (string) = `admin`, поле `name` (string) = ваше ім'я.
7. Готово. Інших людей далі додаєте так: створюєте користувача в Authentication → Users, і на сторінці **«Доступи та дані»** в самому AdminHub додаєте його email з потрібною роллю.

---

## 3. Публікація на GitHub Pages

1. Створити репозиторій (наприклад `adminhub`) і завантажити **всі файли з цієї папки** в корінь.
2. Settings → **Pages** → Source: *Deploy from a branch* → `main` / `(root)` → Save.
3. Через 1–2 хв додаток буде на `https://ВАШ-ЛОГІН.github.io/adminhub/`.
4. На телефоні: відкрити адресу → «Поділитися» → **«На початковий екран»** (iPhone) або меню → **«Встановити застосунок»** (Android).

**Оновлення:** після зміни файлів збільште `VERSION` у `sw.js` (напр. `adminhub-v2`), щоб телефони підхопили нову версію.

## 4. Безпека — як це влаштовано

**Чому `apiKey` можна тримати у відкритому репозиторії.** У Firebase `apiKey` — це не пароль, а адреса вашого проєкту; браузер усе одно його бачить у будь-якому веб-застосунку. Тому захищає не прихованість ключа, а такі шари:

| Шар | Що робить |
|---|---|
| **Firebase Auth** | Без логіна й пароля немає жодного запиту до даних. Захист від перебору паролів вбудований у Firebase. |
| **Закрита реєстрація** | Акаунти створює лише адміністратор у консолі. |
| **Список `members` + правила Firestore** | Навіть якщо хтось якось отримає акаунт у Firebase Auth, без запису в `members` він не прочитає жодного документа. Писати можуть лише Редактори/Адміни, керувати доступами — лише Адміни. Решта бази закрита повністю. |
| **Обмеження ключа за доменом** (зробіть обов'язково) | Google Cloud Console → APIs & Services → **Credentials** → *Browser key (auto created by Firebase)* → **Website restrictions**: `https://ВАШ-ЛОГІН.github.io/*` (і `http://localhost:8000/*` для тестів). **API restrictions**: Identity Toolkit API, Token Service API, Cloud Firestore API, Firebase Installations API. Тепер ключ не працює з чужих сайтів. |
| **Content-Security-Policy** | В `index.html` дозволено завантажувати скрипти лише з власного домену та Firebase — це захищає від впровадження стороннього коду. |
| **`noindex`** | Сторінка не індексується пошуковиками. |
| **«Запам'ятати на цьому пристрої»** | Якщо зняти галочку — сесія закінчується при закритті браузера, а дані сайтів не записуються на диск (лише в пам'ять вкладки). Для чужих комп'ютерів. При виході локальний кеш даних очищується. |

Додатково (за бажанням): **App Check** з reCAPTCHA Enterprise — блокує запити, що йдуть не з вашого додатку.

> Самі паролі від адмінок сайтів у AdminHub **не зберігаються** — лише посилання. Не додавайте паролі в описи.

## 5. Формат даних (для імпорту JSON)

Один документ `sites/{id}` = один сайт з усіма розділами і посиланнями:

```json
{
  "sites": [
    {
      "id": "sage-shop",
      "name": "Sage Shop",
      "url": "https://sage-shop.com.ua",
      "adminUrl": "https://sage-shop.com.ua/admin/",
      "color": "#4f46e5",
      "order": 1,
      "note": "Особливості CMS, кого питати",
      "sections": [
        {
          "id": "product",
          "icon": "🛍️",
          "title": "Сторінка товару",
          "note": "",
          "links": [
            { "id": "price", "title": "Ціна та акції", "url": "https://…/admin/…", "desc": "Вкладка «Дані» → «Ціна»", "tags": ["ціна", "знижка"] }
          ]
        }
      ]
    }
  ]
}
```
Найпростіше: зробіть **Експорт JSON**, допишіть у файлі й зробіть **Імпорт** — сайти з тим самим `id` замінюються.

**Порада щодо посилань.** Деякі CMS (напр. OpenCart 3) додають у посилання адмінки токен сесії (`user_token=…`). Такий токен змінюється після кожного входу — у AdminHub зберігайте посилання **без** нього; якщо CMS перекине на сторінку входу, після логіну відкрийте посилання ще раз.

## Файли

| Файл | Призначення |
|---|---|
| `index.html` | Сторінка + політика безпеки (CSP) |
| `app.js` | Уся логіка: вхід, сайти, пошук, редагування, ролі |
| `styles.css` | Дизайн (світла/темна тема, мобільна версія) |
| `firebase-config.js` | Ваші ключі Firebase |
| `firestore.rules` | Правила доступу — вставити у Firebase Console |
| `demo-data.js` | Приклад даних для демо-режиму |
| `sw.js`, `manifest.webmanifest`, `icons/` | Встановлення на телефон, робота при слабкому інтернеті |
